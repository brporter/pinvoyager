Phase 1

PinVoyager Design System

Tokens, components, screens, and flows for a public photo-travelogue site. Everything here is self-contained HTML and CSS — no build step, no framework, no network requests. Open any page directly.

tokens.css is the source of truth. Every page below consumes it, and phase 6 imports the same file directly rather than transcribing its values into a JavaScript theme object. Changing a token here is meant to change the running application.

Foundations

Color Ramps, semantic tokens, and every approved pairing with its measured contrast ratio. Typography System font stack, nine-step scale, weights, line height, measure. Space, radius, elevation, motion 4px spacing base, six radii, four elevations, four durations, layout constants.

Components

Buttons Four variants, three sizes, every state. Icon and loading treatments. Provider sign-in buttons Google, Apple, Microsoft, Facebook — following each provider's mandated branding. Form controls Inputs, textareas, selects, checkbox, switch. Deliberately small — no credentials exist. Navigation Desktop top bar, mobile tab bar, avatars, signed-in and signed-out states. Photo primitives Frames, grid, filmstrip, selection, captions, and the unplaced treatment. Map primitives Pins, clusters, granularity areas, attribution, controls, dark basemap. Upload Dropzone states, per-file progress and errors, batch summary. Granularity selector The four precision steps, live area preview, and the EXIF-stripping guarantee. Feedback & empty states Badges, toasts, empty states, error states, loading skeletons.

Screens

Each at 390px and 1180px, with annotations explaining the decisions.

Discover Public landing and browse. Signed-out visitors are first-class. Voyage detail The core screen. Desktop split, mobile map-plus-sheet, bidirectional selection. Photo lightbox Single photo, minimal chrome, coordinates labelled with their precision. Upload flow Choose, process, review. Mixed-outcome batches made legible. Voyage create & edit Metadata, photo management, granularity, and the publish decision. Public profile A creator and their voyages. Owner view shows drafts; public view does not. Account settings Profile, default precision, linked providers, deletion. No password section. Sign in Four buttons. First sign-in is signup. Auth callback & failures Verifying, cancelled, provider conflict, expiry, verification failure. 404 & errors Unknown URL, unavailable voyage, server error. Drafts 404 rather than 403.

Flows

Annotated diagrams with failure branches drawn, not just the happy path.

Authentication Sign-in, provider linking, session expiry. Every verification gate shown. Upload pipeline Validation order, storage, EXIF, variant stripping, the no-GPS branch, serving. Voyage lifecycle Draft to published and back, plus voyage and account deletion.

Decisions this design assumes

DecisionConsequence visible in the design
No credentials are ever storedNo signup screen, no password field, no reset flow, no recovery path
Social sign-in onlySettings warns before unlinking a sole provider and prompts for a second
All voyages are publicStated at sign-in; drafts exist so nothing is public while half-built
Derived variants are stripped of metadataThe guarantee appears at upload and at the granularity control
Self-hosted OpenStreetMap tilesAttribution on every map; no API key or vendor branding anywhere
Geocoding deferredCoordinates and precision labels only — no place names in any screen

The full reasoning for each lives in docs/decisions.md.
