Buttons

Four variants, three sizes. One primary action per view — if a screen appears to need two, one of them is secondary.

Variants and states

The secondary button's border uses --pv-border-strong, not --pv-border. It is a control boundary, so it must reach the 3:1 non-text contrast floor. The decorative border token measures 1.45:1 and would leave the button's edge invisible to many people.

Loading

A loading button keeps its label and therefore its width, so the surrounding layout does not jump when the state changes. The spinner is added beside the label rather than replacing it.

The small button is 32px tall but still claims a 44px hit area. min-height: var(--pv-touch-min) is set on every variant. Visible size and touch size are separate concerns, and on a phone the touch size is the one that decides whether the control is usable.

Icon buttons

Every icon-only button carries an aria-label. An icon with no accessible name is unusable with a screen reader, and this is the single most common accessibility defect in interfaces of this kind.
