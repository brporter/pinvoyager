Form controls

There is very little form work in this product — no registration, no password reset, no credential management of any kind, because authentication is delegated entirely. What remains is voyage metadata and account settings.

Inputs are 16px, and that is not a style choice. iOS Safari zooms the viewport whenever a focused input has a font size below 16px. The zoom does not reverse cleanly, so the user is left with a horizontally shifted layout mid-form. Labels can be 12px; the input itself cannot.

Error states carry an icon and a text message, not just a red border — color alone is never the sole signal. The error is associated with the input via aria-describedby so a screen reader announces it on focus rather than leaving the user to discover a validation failure by trial.

What is deliberately absent

No password field, no confirm-password field, no password strength meter, no email-verification input, no security-question control, no CAPTCHA. Authentication is delegated to the providers and no credential is ever stored, so none of these components exist — which is a large part of why the form layer here is so small.
