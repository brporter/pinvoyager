Foundations

Color

Photographs are the content of this product, so the interface is deliberately desaturated. One accent hue carries interaction; a separate warm hue is reserved for map pins, so a pin never reads as a button.

Every ratio on this page is measured, not estimated. Each was computed from the exact token values in tokens.css using the WCAG 2.1 relative luminance formula. If a token changes, these numbers must be recomputed — a contrast claim that drifts from its token is worse than no claim.

Non-text contrast

Control boundaries, focus indicators, and map markers must reach 3:1 against what surrounds them (WCAG 1.4.11). Purely decorative separators are exempt — but the distinction is where this is easy to get wrong.

Two border tokens exist, and they are not interchangeable. --pv-border measures 1.45:1 and is for decorative dividers and card edges only. Any control boundary — text input, select, checkbox, secondary button — must use --pv-border-strong, which measures 3.42:1. Using the decorative token on an input produces an outline a large number of people simply cannot see.

White text on --pv-pin measures 3.83:1 and is not approved. It is listed here because it is the obvious thing to reach for. Cluster bubbles carry a count, so they use the darker --pv-cluster-bg instead, which reaches 5.60:1. Never place text directly on --pv-pin.

Color is never the only signal

Status, selection, and validation state each carry a second cue — an icon, a shape change, a text label, or a weight change. A user who cannot distinguish the accent teal from the pin amber must still be able to tell a selected pin from an unselected one, and the accent and pin hues were chosen partly because they differ in lightness as well as hue.
