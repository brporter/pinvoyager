Auth callback and failure states

Everything that happens after the redirect. These are the states most likely to be improvised in code if they are not designed, and several of them are security-relevant.

The provider-conflict state is the one that matters most. Two providers can return the same email address for the same human, but not every provider verifies address ownership — so silently merging accounts on a matching email is an account-takeover vector. The design refuses the merge and requires an explicit, authenticated link instead.

Apple's first-authorization behavior

Apple returns the user's name only on the very first authorization, in the form-POST body, and never again — not on any subsequent sign-in. If it is not captured at that exact moment it is gone permanently, and the account has no name to display or derive initials from.

This is why the avatar component has an initials fallback and the initials themselves have a fallback. It is not defensive over-engineering; it is the documented behavior of one of the four required providers.
