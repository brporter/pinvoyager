404 and error states

Three distinct situations that look similar and are not: a URL that never existed, a voyage that was deleted, and a draft the visitor is not allowed to know about.

A draft returns 404, not 403. Returning "forbidden" would confirm that a voyage exists at that address, letting anyone enumerate unpublished work by probing IDs. The response is indistinguishable from a URL that was never valid — which is the point, and it means the design cannot offer a "request access" affordance without undoing it.

The three cases

404 · unknown URL
PinVoyager

Nothing here

This page does not exist. It may have been a mistyped address, or a link that has since moved.

Voyage deleted or unpublished
PinVoyager

This voyage is no longer available

It may have been deleted or made private by the person who created it.

Server error
PinVoyager

Something went wrong

This is our fault, not yours. Trying again often works.

Annotations

1The deleted-voyage copy is deliberately non-committal. "May have been deleted or made private" covers both a genuinely removed voyage and a draft the visitor must not learn about, using one message for both so the two cases stay indistinguishable.
2The server error shows a reference ID and nothing else. The user gets something concrete to quote; the stack trace and real cause stay in the server log, where phase 2's error type puts them.
3"This is our fault, not yours." A 500 following an upload leaves people assuming they did something wrong and hesitant to retry. Saying otherwise costs a line.
4Every error state offers a way onward — Discover, browse, or retry. A dead end with no next action is where sessions end.
